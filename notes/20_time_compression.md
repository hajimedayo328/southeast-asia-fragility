## §2 時間スケール変換関手 σ: Time_fast → Time_slow

### 2.1 定義

2つの時間圏 `Time_fast` と `Time_slow` を考える:
- Time_fast: 例えば「年単位」(ASEAN 2010-2026 = 16年)
- Time_slow: 例えば「世紀単位」(米国 1913-2026 = 113年)

時間スケール変換関手 `σ: Time_fast → Time_slow` は時間を **伸縮** する関手:
- `σ(t) = α · t` (`α > 0` が圧縮率)
- α > 1: 拡張 (slow を fast に圧縮)
- α < 1: 圧縮 (fast を slow に拡張)

時間圏は thin category なので、σ は **連続な単調増加関数** (実数値関数として扱える)。

### 2.2 圧縮の例

東南アジア vs 先進国の Trust 時系列を **同じ時刻軸** で比較する場合:

```
σ: Time_KH → Time_US   (KH Bakong の 6年を US Fed の 113年にマッピング)
σ(t) = (113/6) · t ≈ 18.83 · t
```

つまり「Bakong での 1年」が「US Fed での 18.83年」に相当。

これが「時間圧縮係数 α = 18.83」の数学的表現。

### 2.3 関手としての σ

σ は **時間圏 Time の自己関手** (Time → Time) の特殊例。
任意の monotone 連続写像は σ として使える。

monoidal 構造 (時間の合成) に関して σ は monoidal 関手:
- `σ(t_1 + t_2) = σ(t_1) + σ(t_2)` (線形 α なら成立)
- 非線形 σ なら lax monoidal

## §3 Trust 関手の時間圧縮

### 3.1 関手の合成

時間圧縮した Trust 関手:

```
Trust_compressed = Trust_KH ∘ σ : Time_US → H
```

これで「Bakong の Trust」を「US Fed の時刻軸」で見る。

### 3.2 グラフ的解釈

時刻軸を横に、Heyting値階数を縦に取って:
- Trust_US: ゆるい右肩上がり (113年で ⊥ → ⊤_pub)
- Trust_KH: 急峻な右肩上がり (6年で ⊥ → ⊤_pub)

両者を同じスケールで描くと、KH は US より **18.83倍速い** ことが視覚的に分かる。

### 3.3 圧縮率 α と速度比

```
速度 v = dTrust/dt の平均

v_US = (⊤_pub - ⊥) / 113 = 3/113 階段/年 ≈ 0.027
v_KH = (⊤_pub - ⊥) / 6   = 3/6   階段/年 = 0.5

v_KH / v_US = 0.5 / 0.027 ≈ 18.5  ≈ α
```

→ **圧縮率 α = 速度比** (この場合)。

## §4 速度-集中度トレードオフ定理 (試案)

### 4.1 主張

**Theorem (Time-Concentration Trade-off)** (試案):
backbone N の Trust 上昇速度 `v_N` と 集中度 `C_N` (HHI類似) について:

```
v_N × C_N ≥ K_const
```

ここで `K_const` は「自然定数」(物理学の Planck定数のような感じ)。

直感: 「速く強くなりたい → 集中するしかない」「分散したい → ゆっくりにしかなれない」を表す。

### 4.2 観察データ (試算)

ASEAN各国 + 先進国の (v, C) 散布図:

| backbone | v (階段/年) | C (HHI推定) | v × C |
|---|---|---|---|
| KH Bakong | 0.5 | 0.7 (中銀単独) | 0.35 |
| TH PromptPay | 0.3 | 0.9 (BoT) | 0.27 |
| MY TNG | 0.05 | 0.62 (TNG ewallet) | 0.031 |
| VN MoMo | 0.06 | 0.56 | 0.034 |
| PH GCash | 0.05 | 0.85 | 0.043 |
| SG PayNow | 0.04 | 0.6 (bank consortium) | 0.024 |
| US Fed | 0.027 | 0.5 (1中銀+商業銀行) | 0.014 |
| EU SEPA | 0.11 | 0.3 (多銀行分散) | 0.033 |
| JP 銀行 | 0.020 | 0.4 (3メガ+地銀) | 0.008 |

→ `v × C` の値は範囲がある (0.008 〜 0.35)。
`K_const` を「下限」と取ると、最弱が JP 銀行の 0.008 程度。

これだと「定理」じゃなく **「観察的傾向」** に留まる。
真の定理化には:
- 統計的に有意な下限を統計検定で示す
- または「特殊構造下でこの不等式が成立する」と限定する

### 4.3 厳密化の方向

候補1: **物理学アナロジー** (情報熱力学風):
- 「Trust 上昇速度」= 「情報処理速度」
- 「集中度」= 「自由度の縮小」
- これらが第二法則的にトレードオフ

候補2: **monoidal 圏論的構成**:
- 並列 backbone (⊗_∨) の場合: `v_total = max v_i`、`C_total = max C_i`
- これらの積が定数になる条件を categorical に書く

候補3: **計算量論**:
- Heyting値の更新速度は backbone の構造依存
- 集中構造 → 直接更新可能、分散構造 → 同期コスト

→ **本プロジェクトでは候補1 (物理アナロジー) を中心軸** に。「情報熱力学的トレードオフ」として位置づける。

## §5 時間圧縮の代償 — Heyting値の犠牲

### 5.1 主張

時間圧縮 α が大きいほど (= 速い backbone ほど)、何かの **Heyting値が犠牲** になる。

具体的に犠牲になるもの:
- **分散性 (Decentralization)**: 集中構造で速さを実現
- **法的多層保護 (Multi-layer Legal Protection)**: 1機関依存
- **歴史的検証可能性 (Historical Verification)**: 短期間では蓄積できない

### 5.2 圏論的書き方

Trust 関手 + 副作用関手:

```
Trust:     Time → H_main         (主要な信頼値)
Sacrifice: Time → H_sacrifice    (犠牲値、逆方向)
```

そして:
```
Trust(t) × Sacrifice(t) = const  (反比例)
```

これは Heyting代数の **反順序** で表現可能 (大なら小、小なら大)。

### 5.3 ASEAN実証

| backbone | 圧縮 α | Trust(2026) | Sacrifice (推定) |
|---|---|---|---|
| KH Bakong | 18.8 | ⊤_pub | 単一中銀依存 (政治変動リスク) |
| TH PromptPay | 11.3 | ⊤_pub | 軍政依存 (頻発するクーデター) |
| US Fed | 1.0 (基準) | ⊤_pub | 分散構造 (3000銀行) |
| EU SEPA | 6.3 | ⊤_bank | 多国合意 (各国合意難) |

→ **東南アジアの「ふらん早期到達」は「政治変動リスク」を犠牲にしている**。

これが「時間圧縮の代償」の具体的中身。

## §6 Future Projection — 時間関手の外挿

### 6.1 関手の補間と外挿

実データから Trust 時系列が得られたら、関手の **補間** で過去・**外挿** で未来を予測:

- 補間: `Trust(t_unknown) ≈ Trust(t_known) ∨ ... ` (近隣値から推定)
- 外挿: `Trust(2030) = ?` (将来予測)

外挿は数学的にハード (関手の universal property だけでは決まらない)。
仮定が必要:
- monotone (単調増加) → これは関手性で自動
- 加速度ゼロ → 一次外挿 (線形補間)
- 加速度減衰 → サチる予測

### 6.2 backbone 別の将来予測

```
PH GCash (2026 ⊤_priv で頭打ち):
  → 2030予測: ⊤_priv 維持 (頭打ち継続)
  または: GCash IPO で ⊤_bank 化 (Mynt 上場で institutional 圧)

KH Bakong (2024 ⊤_pub):
  → 2030予測: ⊤_pub 維持 (政治安定なら)
  または: 中国デジタル人民元統合で ⊤_pub_CN (subordinated) リスク

US Fed (2026 ⊤_pub):
  → 2030予測: ⊤_pub 維持 (CBDC化検討中)
```

これは政策シナリオ分析として実用可能。

## §7 先行研究 (Jia-Mitani / Floridi-Jia-Tohmé 系) との接続 — 時間軸での

### 7.1 Jia 2024 Heyting Origami との対応

折り紙の操作は **時間軸で積み重なる**:
- 1回目の折り → 紙の状態が変わる
- 2回目の折り → さらに変わる
- 折り順 = 時刻順

→ Jia 2024 で扱う Heyting代数値の状態遷移は、本プロジェクトの時間関手 Trust と **同型**。

### 7.2 時間圧縮の折り紙版

折り紙で「速く折る」と:
- 折り目が雑になる (Heyting値が下がる)
- ミスが多い (失敗確率上昇)

→ 折り紙でも **「速度 vs 精度のトレードオフ」** が存在。
これは本プロジェクトの「速度-集中度トレードオフ」と同じ構造の可能性。

Jia-Mitani 2024 "Heyting Algebra in Flat Origami" の枠組みで時間圧縮の研究をすると、新規貢献候補。

## §9 まとめ

時間圧縮の数学的フレーム:

```
時間圏 Time + 時間スケール変換関手 σ
   ↓
時間圧縮率 α が速度比に対応
   ↓
速度-集中度トレードオフ: v × C ≥ K_const (試案)
   ↓
時間圧縮の代償 = 分散性 / 法的保護 / 歴史的検証可能性 の犠牲
   ↓
Future Projection (外挿) で 2030 予測可能
```

→ 本プロジェクトの「東南アジアは先進国の予言」が **時間軸の数学** で正当化される:
- 東南アジアは時間圧縮で `⊤_pub` に到達
- ただし「集中構造」「政治依存」を犠牲にしてる
- 先進国は将来同じトレードオフに直面する (例: 米国 CBDC、EU SEPA 拡大)

これで notes/19 (時間圏 universal property) と組み合わさって、「時間軸研究」の **完全な数学的基盤** が固まる。

### §10.1 構造的結論 — 不変量はスカラーでなく型 (2026-06-07)

圏論プロジェクトなのでスカラー相関で終わらせず、**構造的不変量**で結論を出す
(`src/h_petri/empirical/structural_conclusion.py`)。

- **S1 直交性**: backbone 型が包摂水準の分散をどれだけ説明するか → **η² = 0.004**
  (ほぼ 0%)。同じ型が包摂レンジ全体に散る(中銀型 TH 96 vs KH 33、platform も分散〜独占)。
  → **型(構造)とスカラー包摂は直交** = 互いに独立な情報。
- **S2 型 → Heyting バックストップ深度**は単調順序不変量 `⊤_priv < ⊤_bank < ⊤_pub`
  (= 保証の深さ。data/backbone_facts.py から (c) 級)。
- **S3 故障モードは型の関手**(スカラーでなく): platform=単一企業崩壊・利用者が損失負担 /
  bank=預金保険でキャップ / 中銀型=主権バックストップ(政治リスク型、商業崩壊しない)。

**構造的結論**:
> スカラー包摂 ⟂ backbone 型(η²≈0)。脆弱性を支配する不変量は**圏論的な型(=バックストップ
> 深度)**で、スカラーには見えない質的・順序的事実。だから §10 の負の相関(ρ≈−0.08)は
> **想定通り**で、「脆弱性は構造軸に乗る」signature。**ここで圏論が元を取る** — 金融包摂
> 統計が盲目な不変量(誰がバックストップし、どう壊れるか)を名指しできる。

⚠️ 限界: n=8、S3 は制度的事実であって定量 outage データセットではない(型別の障害頻度・
深刻度の定量化が次)。η² も小群で noisy。出力: `docs/data/structural_conclusion.json`。

### §10.2 S3 を実 outage データで定量化 (2026-06-07)

S3(故障モードは型の関手)を、出典付きの実障害イベントで定量化した
(`src/h_petri/empirical/failure_modes.py`、literature/raw/10 ベース、GCash reconciliation
と PromptPay/ITMX 2022 を再検証)。documented events を構造軸でクロス集計:

- **SCOPE × 運用トポロジ**: single-operator(platform)→ **total** 全停止(5/5)、
  federated 共有レール(PromptPay/ITMX)→ **distributed** 銀行別に分散(2/2)
- **LOSS-BEARER × バックストップ型**: platform(⊤_priv)→ **users** が損失負担(5/5)、
  federated/central → **banks/system**(2/2)

**構造的結論(S3、データ支持版)**:
> 故障モードは **2つの構造軸**に分解される — SCOPE は運用トポロジ(単一社 vs 共有レール)に、
> LOSS-BEARER は Heyting バックストップ型に効く。**どちらもスカラー普及率と無関係**。
> つまり「どう壊れ、誰が損するか」を支配するのは圏論的構造であってスカラーではない。

⚠️ **正直な限界**:
- 小 n(各セル 2〜5件)。**統計でなく図示レベル**。
- この n では **2軸が分離しきれない**(platform=single=民間、PromptPay=federated=中銀義務が
  偶々揃ってる)。「2つの独立軸」は**仮説**であって、分離証明ではない。
- **頻度は型間で比較しない**(literature/raw/10 自身が警告: Bakong=0件は NBC 自己報告 +
  KH/VN の英語報道過小 = 開示バイアス)。主張は「**how/who**(モード)」だけ、「**how often**」は外す。

→ それでも S3 は「制度的定義」から「**出典付きの観測パターン**」に一歩進んだ。
出力: `docs/data/failure_modes.json`。

### §10.4 v×C をついに直接テスト — トレードオフは相関でなく不等式 (2026-06-12)

Findex の 2017 波と 2021 波(両方 WB API)から **普及速度 v = Δmobile money / 4年** を
計算し、§4 の v×C 仮説を初めて直接テストした(`src/h_petri/empirical/speed_test.py`、n=7、
LA は 2017 null・VN は 2021 null で除外)。**2つの読みを分けてテスト**:

**(1) 相関読み「速い国ほど集中」**: Pearson r=+0.21、Spearman ρ=**−0.05** → **3度目の null**。
account(ρ=−0.08)・mobile money 水準(ρ=+0.18)・速度(ρ=−0.05)— **3つ全部の
スカラー版が外れた**。発見5(脆弱性は構造に乗る)がさらに頑健に。

**(2) 不等式読み「速い AND 分散は不可能」(=排除領域)**: トレードオフの正しい形は
**bound であって slope ではない**(v×C≥K 型の主張は散布図の「角が空」を予言するだけで、
相関を予言しない)。データ:
- 速い国(v≥4pp/yr): TH 12.9 / MM 7.1 / SG 5.3 / PH 4.3 / MY 4.3 → **全部 conc≥60%**
- 分散国(conc<50%): **ID(25%)のみ** → v=1.5pp/yr で遅い
- **「速い AND 分散」の角は空** = §4 の bound 版と整合

⚠️ **正直な評価**: 分散国が ID 1国しかないので、空の角は偶然でも説明できる。
n=7・閾値(v≥4, conc<50)も著者選択。「仮説と整合」止まりで「確認」ではない。
本当に角をテストするには**域外データ**(インド UPI、ブラジル Pix、ケニア M-Pesa)が要る。

**構造的な教訓**: 「トレードオフ」を相関でテストするのはカテゴリーエラーだった。
束・順序で考えるこのプロジェクトの流儀なら、最初から**不等式(排除領域)**として
定式化すべき主張。3つの null は「スカラーの slope は無い」を言ってるだけで、
bound はまだ生きている。出力: `docs/data/speed_empirical.json`。

### §10.5 域外 corner テスト — bound は「測るレベル」で運命が分かれた (2026-06-12)

bound の最強反例候補 = **インド UPI / ブラジル Pix / ケニア M-Pesa** で角を攻めた
(`src/h_petri/empirical/corner_test.py`、全ケース出典付き・2026-06-12 検証)。

**鍵データ**:
- **Pix**: 中央銀行(BCB)運営、2020-11 開始 → **1年で成人の67%**(114M、~67pp/年 =
  ASEAN 最速 TH の5倍、史上最速の決済普及)→ 2025 には成人の~91-93%。
  フロントエンドは**全銀行・フィンテックアプリに分散**(支配的アプリなし)
- **UPI**: NPCI(銀行コンソーシアム)単一レール、トップアプリ PhonePe **47.7%**(<50)+
  GPay 36.7% の duopoly
- **M-Pesa**: 単一民間、シェア96.5%、Findex 2021 で成人68.7% — 全レベルで集中(整合)

**判定 — bound は「集中をどのレベルで測るか」で分裂**:
- **アプリレベル: FALSIFIED**。Pix は史上最速かつ支配的アプリなし。UPI もトップ<50%。
  「速い AND (アプリ)分散」の角は**埋まってる**
- **レールレベル: 生存**。速い普及は ASEAN でも域外でも例外なく**単一共有レール**
  (BCB / NPCI / Safaricom / ITMX)に乗ってる。ただし「相互運用の速さはレール1本から来る」
  ので**ほぼ定義的** — 大胆な予言ではなく構造的観察

**精密化された構造的結論(本プロジェクトの中で最も引用可能な一文)**:
> **速さは「レール1本 = stalk 1本」を要求する。アプリを複数にしても stalk は消えない。
> 「stalk を無くす」という選択肢は存在せず、選べるのは stalk の後ろに誰が立つか
> (Heyting バックストップ: Pix ⊤_pub / UPI コンソーシアム / M-Pesa ⊤_priv)だけ。**

これで v×C(§4)→ 単一 stalk の sheaf 分析(notes/25)→ バックストップ型(発見5)が
**1本の線**に繋がった。Cloudflare/M-Pesa の H¹ 物語はレールレベルで普遍。

⚠️ 限界: 速度の単位がケース間で完全には揃わない(Findex pp/年 vs プラットフォーム
ユーザー成長)。Pix のフロント別シェアは未公表(全銀行アプリ設計からの推論)。
UPI 47.7% は閾値50%に対し borderline。Findex mobileaccount 指標は UPI/Pix を
捕捉しない(IND 10.4% / BRA 27.0%)— 指標が「口座の型」を測ってて「機能」を
測ってない、というそれ自体が「構造が大事」の傍証。
出力: `docs/data/corner_test.json`。

### §10.7 第3波(Findex 2025)での時間軸検証 — stalk 結論の out-of-sample 的中 (2026-06-12)

時間軸は実証の最弱リンクだった(2波しかない)。**Findex 2025 波(2024年調査)が
WB API で取得可能になった**ので、第3波で時間軸の主張を検証
(`src/h_petri/empirical/wave3_test.py`):

**(1) 速度の持続性: 無い**。Spearman(v17-21, v21-24) = **−0.20**。
TH は最速(12.9pp/年)→ マイナス(−6.1)、ID は最遅級(1.5)→ 加速(4.2)。
速度は国の安定的性質ではない = スカラー指標の時間的不安定性。「構造>スカラー」をもう1票。

**(2) 角の再チェック — ASEAN 域内で角が埋まった、しかも予言通りの形で**:
- ID が v=4.24pp/年 に加速、ウォレット集中は 25-31% のまま → 「速い AND ウォレット分散」
  の角が**域内で占有**された(§10.4 のウォレット級 bound は域内でも死亡)
- **だが加速の窓(2021→2024)は QRIS(2020)+ BI-FAST(2021-12-21 ローンチ、
  2024年までに123行参加、出典: BI公式/Vixio/Central Banking)の登場と一致**
- つまり ID は「**単一の中銀共有レールを得て初めて速くなった**」— レール無し時代(17-21)は
  遅く、レール獲得後(21-24)に加速、アプリ複数性は不変

→ **§10.5 の stalk 結論の out-of-sample 的中**。Pix/UPI(域外)から導いた
「速い+アプリ分散は、単一共有レールがある時だけ可能」が、その後に見た第3波データの
ID で**域内再現**された。1国の自然実験(反実仮想なし)という限界はあるが、
レベル分割結論が新データで生き残った/強まったのは本物の検証。

**(3) 異常値(解釈せず旗のみ)**: TH 60→41.7(実減か Findex 分類変更か未確定、結論から除外)。
MM は 2024 null(内戦で調査不能 — 「測定の可用性も政治的」)。
