Heyting-valued Petri Net: simulating ASEAN mobile money backbones.

同じ場所数、同じ遷移数、同じ送金回数。
でも 不可視層の Heyting値の上限が永久に違う。
これが「業界レポートの分類」を「数学的構造」として再現したもの (実データ証明ではなくモデルでの再現)。

Petri net は「並行して何かが動くシステム」を数学的に書く道具。1960年代に提案されてから、半導体回路・並行プログラム・生体反応の解析に使われてきた。

本プロジェクトでは、これを Heyting値拡張 (Jia & Mitani 2024 "Heyting Algebra in Flat Origami" の発想を借用) して、ASEAN モバイル金融に当てる。

結果: Bakong (中銀型) と GCash (民間型) は 同じ構造の Petri net なのに、トークンの値の上限が永久に違う。これは「中央銀行は国家保証、民間は企業保証」の 圏論的根拠。

§ P1 — WHAT IS A PETRI NET

Petri net とは 50秒で

場所 (○) と 遷移 (□) の2種類のノードを矢印で繋いだグラフ。場所に トークン (●) が乗っていて、遷移が発火するとトークンが移動する。これだけ。

並行性 (同時に複数の遷移が動ける) を扱えるのが特徴。

最小例: トークンが UserWallet → Pending → Recipient に流れる Petri net
§ P2 — HEYTING-VALUED EXTENSION

Heyting値 Petri Net = 不可視層を入れた拡張

標準 Petri net は、トークンの数を 0, 1, 2, ... という自然数で扱う。しかし「信頼」「証拠」「確実性」は数で測れない。「あるか、ないか」じゃなく「どれくらい強い証拠か」。

そこで Heyting代数 (直観主義論理の真理値) で測る。Jia & Mitani 2024 の Flat Origami研究で使われてる発想を Petri net に持ち込む。

本プロジェクトでは4段階の Heyting代数を採用:

⊥
BOTTOM
証拠なし
⊤_priv
PRIVATE
民間企業の保証
⊤_bank
BANK
銀行法+預金保険
⊤_pub
PUBLIC
中央銀行・国家保証

この4段階は Heyting代数の半順序: ⊥ ≤ ⊤_priv ≤ ⊤_bank ≤ ⊤_pub。
左が「弱い証拠」、右が「強い証拠」。Heyting代数の演算 ∨ (合体) は 常に上を取る ので、 一度 ⊤_pub に到達した場所は二度と ⊤_priv には戻らない。これが「信頼の累積」を構造的に保証する。

§ P3 — COMMON CPN SPEC

共通CPN規約: 同じ枠で4タイプを比較

Bakong も GCash も 同じ場所、同じ遷移、同じ流れ で書く。違うのは「不可視場所に追加される Heyting値の上限」だけ。

これで「同じ枠の中で何が違うか」が比較可能になる。

可視層 5場所 (UserWallet → PendingTx → Backbone → SettledTx → RecipientWallet) と 不可視層 2場所 (TrustHub, SystemicLoad) の計 7場所、 遷移 5本 (InitiateSend → BackboneClear → Settle → Reconciliation → AcknowledgeReceipt)。 どの backbone でもこの構造は同じ。違うのは 各遷移が不可視場所に書き込む Heyting値の大きさだけ。

詳細は notes/07 共通CPN規約。

同じ構造、違う Heyting値の上限 — 自然変換 η の正体

両者の差は圏論的には 自然変換 η: F_GCash ⇒ F_Bakong として書ける。 成分は η_TrustHub: ⊤_priv → ⊤_pub という Heyting半順序の包含。

仮説 P4-C · 律速逆転 (notes/15)

同じ4 backbone でも、合成方向で律速が逆転する

4つの backbone を「並列に並べる (⊗)」と最強の Bakong (⊤_pub) が全体を引き上げる。 でも「越境決済として統合する (▷)」と最弱の GCash (⊤_priv) が全体を引き下ろす。 合成方向で律速が真逆。本プロジェクトの中で唯一「真に新規」だと思った定理 — ただしサーベイで Ghrist-Gould-Lopez 2024 が分配束で同型の定理を既に証明していたことが判明。残る貢献は Open Petri Net / ASEAN応用 / Heyting特有の構造への翻訳。

ASEAN域内決済統合 (Project Nexus 等) は構造的に脆弱性を増やす、という反直観的予言。 数学的根拠は Ghrist-Gould-Lopez 2024 Lattice-Valued Bottleneck Duality。 本プロジェクトは Open Petri Net (Baez-Master 2018) の cospan-pushout 文脈に翻訳。

仮説 P4-D · 場所中心性 (notes/16 主張4)

「構造は同じ、Heyting 値だけが違う」を中心性で再確認

§ P5 — CROSS-DOMAIN · AI DEPENDENCY

同じ枠で AI 領域に当てる

H-Petri Net は モバイル金融専用じゃない。共通CPN規約 (§P3) の 5可視場所 + 2不可視場所 + 5遷移 をそのまま AI 領域に当てると、4 LLM backbone が金融の 4 backbone と 同じ Heyting値階数 で並ぶ。

対応関係 (notes/18 §4):

  • GovAI (仮想・公的) = Bakong (両方 ⊤_pub 公的保証)
  • Llama (Meta 開放配布) = PayNow (両方 ⊤_bank 分散構造)
  • ChatGPT / Claude (民間集中) = GCash (両方 ⊤_priv 単一企業)

§ P6 — SHEAF H¹ · 局所→大域のリスク

共通 stalk の崩壊を H¹ で捕まえる

ASEAN 各国 (or 各 AI サービス) を点、隣接関係を辺とする 1-複体の上に、各点の Trust 値を Heyting値の sheaf として乗せる。すると H¹(F) = 隣接点で値が食い違う辺の数 が「貼り合わせの障害 = 構造的に潜むリスク」を測る。

1997 と Cloudflare で 同じ signature が出る — これが notes/25 の主張。

注意: 下の H¹/H⁰ は実測ではなく、著者が各時点の Trust 値を手で割り当てたモデル上の数値例。 位相空間の定義自体も notes/25 では未確定 (探索段階)。「こう割り当てると枠組みと整合する」というデモであって、データからの検証ではない。

仮説 P6-A · 1997 AFC の H¹ 階段

USD ペッグ崩壊で H¹ が爆発する

1996-12 (USD ペッグ安定) は H¹=0。1997-07 のタイバーツ崩壊で H¹=4。 1997-12 の伝染拡大で H¹=6。共通 stalk (USDペッグ) の崩壊が階段状に H¹ を押し上げる。

仮説 P6-B · Cloudflare 2025-11 の H⁰ 崩壊

共通 stalk の崩壊は H⁰(meet) を ⊥ に落とす

Cloudflare の場合は H⁰(meet) が ⊤_priv → ⊥ → ⊤_priv と落ちて戻る。 これは「共通 stalk が瞬間的に死ぬ → 全域の最弱値が ⊥ に支配される」事象。 1997 とは H¹ vs H⁰ で出方は違うが、共通 stalk 崩壊という構造的事象は同じ。

検証 P6-C · H¹ は前兆か同時か → 両方やった (2026-06)

市場の目には同時指標。ファンダメンタルズを入れると先行指標になる

①教科書的年表(THB 7月→IDR 8月→KR 12月)で検証: 市場可視の Trust 入力では H¹ は発火前に一切動かない = 同時指標(「前兆」主張は撤回)。 ②そこで危機に先行する観測量 — 短期外債/外貨準備(1997年6月末、RBA/BIS: KR 3.0 / ID 1.6 / TH 1.1 / MY 0.6 / PH 0.7)— を Guidotti-Greenspan ルール(比率≤1)で Trust に接続すると: 名目 H¹=0 のまま、実態調整 H¹=6 が発火前に立つ。 不整合エッジは脆弱国 {TH,ID,KR} と健全国 {MY,PH,SG} の境界にぴったり — 実際の被害の濃淡とも整合。「⊤_priv が ⊤_bank を演じる」のデータ駆動版。

正直な限界: これは retrodiction — Guidotti-Greenspan ルールは危機後の 1999年に定式化されたもので、「当時リアルタイムで予言できた」とは主張しない。 1エピソードのみ・SG比率は仮定。偽陽性分析は完了(下 P6-D: 非危機国パネルで実測)。 コード: sheaf/h1_timeline.py / sheaf/h1_leading.py。

検証 P6-D · 真の偽陽性パネル → 「弱いが本物」 (2026-06)

非危機国を含む 113 カ国で測ると、比率>1 は弱いが本物の早期警戒

P6-C / §5.6 が「5カ国(全員が危機当事国)では測れない」と残した真の偽陽性率を、 World Bank WDI の実データ 113 カ国・1975-2022で実測した。シグナル=短期外債/準備>1、 危機=為替からの機械的通貨暴落、早期警戒の作法で平穏年のみ評価。 結果: Guidotti-Greenspan が発火した後 2 年内に危機が来るのは 約 25% (平穏年ベースの 13% の約 2 倍 = lift 1.88) — 弱いが本物のシグナル。 だが裏を返せば発火の約 75% は空振り(偽警報)、さらに危機の 65% は比率≤1 で来る (= P6-C のマレーシア型偽陰性をパネル規模で見たもの)。

§ P7 — WRITER H MONAD · 副作用累積

「便利の暴走」をモナドで書く

H-Petri Net の発火は Writer H モナド (Heyting値ログ付きの計算) と同じ形で書ける。各遷移が「値は変えず、Heyting値の log を累積するだけ」の Kleisli 射として書ける。

このとき 累積順序を入れ替えても結果は同じ。これは厳密には新しい定理ではなく、Heyting半順序の ∨ が結合的・可換・冪等(=有界半束)であることの直接の帰結。下のコードはその性質を実装が正しく満たすことの確認。

仮説 P7-A · 副作用累積の順序非依存性 (∨ の半束性質、証明は標準的)

6個のコストの全順列 720通りで同じ⊤_pubに収束

{⊤_priv, ⊤_bank, ⊤_priv, ⊤_pub, ⊥, ⊤_bank} の 6個を 720 通り並べ替えても、 全ての並べ方で最終ログは ⊤_pub。 これは ∨ の冪等・可換・結合性から数学的に自明な結果で、 新規定理ではなく 実装が半束則を正しく満たすことの確認。

仮説 P7-B · Bridge — 4 backbone を Kleisli chain で再現

同じ chain 長でも backbone タイプで log が分かれる

Bakong, PayNow, KBZPay, GCash の発火列を Writer H 上の Kleisli chain として書き直すと、 §P4 と 完全に同じ階数の分離 (⊤_pub / ⊤_bank / ⊤_priv) が出る。 Petri net シミュレータを動かさずに、モナド演算だけで backbone の構造的差を計算できる。
